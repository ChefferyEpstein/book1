# M08 — Book1 1.9.0 Bokemongs & Social Expansion

**Status:** PLANNED

## Goal

Make Book1 1.9.0 the next major feature release by expanding long-term progression, minigame statistics, social planning, tournament payout clarity, and introducing the first Bokemongs system.

## Release pillars

### 1. Long-term milestone challenges

Add persistent, cumulative challenges that sit above weekly challenges and reward long-term Book1 activity.

Initial examples:

- play 250 pool games
- pot 1,000 balls
- win 100 pool games
- play 100 minigames
- win 50 Connect 4 games
- win 25 Chess games
- sink 100 Battleships ships / achieve an equivalent durable Battleships milestone
- complete 50 weekly challenges
- reach selected Prestige milestones

Requirements:

- progress persists across game weeks
- milestone tiers where appropriate
- clear progress bars / counters
- rewards can include chips, XP, cosmetics, Bokemong unlocks or evolution conditions
- historical data should backfill progress wherever Book1 already stores enough evidence
- no duplicate claiming
- server-side validation for rewards

### 2. Chess & Battleships intelligence reports

Bring Chess and Battleships statistical pages up to the same standard as Connect 4.

Each page should include a dedicated leaderboard / intelligence report with useful long-term stats.

#### Chess

Candidate stats:

- games played
- wins / losses / draws
- win %
- rating
- best win streak
- current streak
- white vs black record
- average game length
- fastest win
- most common opponent
- best victim / worst nemesis
- wins by checkmate / timeout / resignation where available

#### Battleships

Candidate stats:

- games played
- wins / losses
- win %
- win streaks
- current streak
- shots fired
- hits / misses
- hit %
- ships sunk
- average shots to win
- fastest win
- best victim / worst nemesis

Stats should be calculated from historical game records where possible and should not require loading oversized game state for every page view.

### 3. Availability calendar & social events

Ship the existing roadmap scheduler in 1.9.0.

Core functionality:

- create social events
- fixed-date events with In / Maybe / Out RSVP
- flexible-date events with Free / Maybe / Unavailable voting
- show who has and has not responded
- rank candidate dates by attendance
- organiser confirms a winning date
- upcoming agenda
- calendar view
- event detail
- event status: planning / confirmed / cancelled / completed

Initial use cases include poker nights, go-karting, meals, nights out, tournaments and other group events.

### 4. Correct 8-man tournament payout display

Ensure every 8-player tournament clearly shows and applies the payout split:

- **Winner: 75%**
- **Runner-up: 25%**

Requirements:

- visible before entry / tournament start
- visible on tournament detail / bracket
- prize amounts calculated from the actual pot
- winner and runner-up settlement follows the same rule
- admin / results views show the exact paid amounts
- no ambiguity between total pot and per-player contribution

### 5. Bokemongs V1

Introduce Book1's collectible creature system under the final name **Bokemongs**.

V1 target:

- roughly 20 original Bokemongs
- 3 starters
- Bokemong collection / dex
- levels and XP
- rarity
- types
- traits / passive abilities
- small number of evolution chains
- activity-driven unlocks
- rare / alternate variants
- simple 3v3 turn-based battles
- battle history
- basic leaderboard

Existing Book1 activity should feed Bokemong progression and unlocks, including:

- pool
- Connect 4
- Chess
- Battleships
- weekly challenges
- Prestige
- long-term milestone challenges

The system must use original Book1 creatures, names, artwork and mechanics rather than copying protected Pokémon characters or assets.

### 6. Connect 4 live move refresh

Correct the current Connect 4 stale-board behaviour.

Current behaviour:

- actor refreshes immediately after their own move
- opponent can remain on stale board state until the global 30-second version poll or another visibility refresh
- Chess already uses the preferred lightweight realtime pulse + targeted game-detail fetch

Target behaviour:

- subscribe to the existing lightweight Book pulse while an active Connect 4 game is open
- on pulse, fetch only that Connect 4 game through `book_game_detail`
- update board / turn state immediately
- avoid restoring full-state realtime subscriptions or increasing Supabase egress materially
- clean up channel subscription when leaving the game
